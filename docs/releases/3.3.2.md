# Keysoft 3.3.2

Source release: 2026-10-23.

Android production target: versionCode 131.
Google Play status at release creation: Keysoft 3.3.1 / versionCode 130 remains published;
3.3.2 submission is a separate manual step.

Keysoft 3.3.2 fixes a production authentication performance regression, hardens and
clarifies the backup flow, and packages the Nocturne v2 design-system refresh. It does not
change the KS1/KS1-PW1 payload layouts, storage keys, existing vault KDF parameters, Android
permissions, canonical assets, or the offline-only operating model.

## Security And Performance

- Restores native Argon2id in production builds. The Expo Go detection used
  `Constants.expoGoConfig`, which is truthy in standalone builds because expo-constants
  resolves it to the embedded update manifest; production therefore forced the pure-JS
  PBKDF2 fallback (about 6-7 seconds per PIN unlock on a current phone), skipped the native
  KDF and kept local notifications in history-only mode. Detection now relies on
  `executionEnvironment` and `appOwnership`; new vaults use Argon2id and existing PBKDF2
  vaults upgrade transparently on the next PIN login.
- Keeps the shared vault writes serialised and the KDF upgrade/password-change transaction
  crash-safe, including the pending recovery record and the batched re-encryption.
- Backup export and import now show a blocking progress dialog while the password-derived
  key is calculated and the file is written, read or imported, instead of leaving the
  settings screen apparently frozen.

## UI/UX

- Migrates the mobile presentation layer to the documented Nocturne v2 design system:
  responsive compact/medium/expanded/large window classes, a 4pt spacing grid, an explicit
  type scale, modern radii/elevation, contrast-checked semantic colors (`onPrimary`,
  status colors, stronger tertiary text) and an accessibility token set. Documented in
  `docs/design-system.md`.
- `ScreenWrapper` owns the screen gutter and readable content width; screens were migrated
  off ad-hoc width math and literal sizes. Text/form screens cap at 720pt on tablets, the
  vault grid fills two or three columns, and short-landscape, split-view/foldable windows
  and the PIN keypad adapt to the window class.
- Dialog headers stack the icon above a wrapped, centered title/description with a 48pt
  close control; Settings row separators use the divider token; vault cards fill their grid
  slot; the decorative vault-health progress bar was removed; the generator uses the shared
  switch wrapper; and the unlock screen groups identity and keypad evenly.
- Accessibility: 44/48pt touch targets, WCAG AA contrast for secondary/tertiary text and
  status colors in both themes, accessible switch state, and reduced-motion-safe
  transitions.

## Deployment Boundary

The `v3.3.2` tag identifies the exact source used to start the EAS Android production build.
The EAS production profile produces an Android App Bundle and auto-increments the remote
version from 130 to 131. It does not submit to Google Play; store review and publication
remain manual.
