# Keysoft 3.1.0

Android versionCode: 127 (EAS production remote version target)

## Highlights

- Product support moves from the shared Mikesoft web page to email: Settings opens a pre-addressed message to `keysoft@mikesoft.it`, with the address copied to the clipboard when no mail client is registered.
- The privacy notice documents how to delete local data, covering the in-app reset, uninstalling the app, and clearing data from device settings.
- The copied support address is no longer erased by the password clipboard timer, and copy failures are reported instead of failing silently.
- Contact details and privacy-section numbering each live in one place, so the address and the section numbers cannot drift between screens and translations.

## Support Path

- Settings > Support starts a `mailto:` intent directly. Opening a URL is an ordinary activity start and requires no Android package-visibility declaration, while the previous `canOpenURL` check resolved through `queryIntentActivities` and reported false on Android 11 and later, leaving the fallback as the only reachable path.
- When the intent is refused the address is copied and a toast confirms it; a clipboard failure now shows an error toast.
- The address is copied without the password auto-clear timer and any pending clear is dropped, since the clipboard no longer holds a secret. Password copies keep the existing timer behavior.

## Privacy Notice

- New section 9 covers data deletion: the in-app reset path (Settings > Account > Reset App) and what it removes, uninstalling the app, and clearing app data from device settings, with the Android and iOS differences stated plainly.
- Google Play requires a deletion path only for apps that create accounts. Keysoft has no accounts, so the section is a voluntary disclosure kept in sync with the published policy.
- The document revision is tracked as version 3.1, independent of the application build number, so shipping a release no longer requires editing the policy.
- Section numbers are rendered from the screen's heading order. The visible numbering is unchanged; the translated titles no longer carry it.

## Verification

- `bun run typecheck`, `bun run lint`, and `bun run test` (29 suites, 182 tests) pass.
- `bunx expo-doctor` passes 20 of 20 checks after aligning `expo-updates` with the patch version required by Expo SDK 57.
- Android and iOS JavaScript bundles export successfully.
- New ClipboardService tests cover the non-secret copy path; the legal regression test asserts contact details against the shared constants, checks the document version in isolation, and rejects section numbers written back into translated titles.

The Google Play submission remains manual, and iOS stays a cloud-simulator compatibility target rather than an App Store release target.
